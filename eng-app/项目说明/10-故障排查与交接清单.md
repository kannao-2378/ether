# 故障排查与交接清单

## 最短排查路径

| 现象 | 先看什么 |
|---|---|
| /eng/404 | 是否复制dist、/etc/nginx/pels-eng.conf是否include进HTTPS server、静态root是否正确 |
| 页面有了但API404 | BASE_URL=/eng/、代理/eng/api/→8010/api/，不要误走原站8080 |
| 502 | systemctl status pels-english，journalctl -u pels-english，curl本机8010健康接口 |
| 服务resources错误 | /etc/pels/english.env是否存在；密码创建失败不会生成文件 |
| 登录403 | 域名是否kannao.top、Origin和Cookie路径是否一致；www没有单独配置共享来源 |
| 登录后401 | Cookie过期、密码改动、退出撤销；不能直接关掉保护解决 |
| 学习记录像清空了 | 先查PELS_DATA_DIR和使用线上还是localhost，是否导错库/开了测试；不要马上初始化新库 |
| 一直重复少数项 | 新学额度、12项池、前置材料、最近反馈是否独立通过；查看真实queue/task状态 |
| 记忆历史没有下一次日期 | 可能仍在当天题序巩固，应显示隔几题而不是伪造固定时刻 |
| 手机发音无声 | 真机音量、点击手势、当前语音源、音频接口状态、espeak-ng安装、缓存权限 |
| 牛津单词下载失败 | 首次需要服务器联网且来源可访问；失败应显示，不能当已缓存 |
| 深色顶部变浅 | theme-init加载路径、首屏主题缓存、theme-color和iOS安装时状态栏设置 |
| 键盘关闭栏晚一拍 | visualViewport时机、事件/布局；必须iOS真机验证，不能靠电脑模拟下保证 |
| 导航滚动文字重叠 | 导航背景是否又改透明、z-index层级；当前使用实色主题背景 |
| Windows备份失败 | 任务结果、download.log、联网、admin密钥、known_hosts、服务器ZIP可读权限 |

线上查看日志（不要输出登录配置正文）：

```bash
sudo systemctl status pels-english --no-pager
sudo journalctl -u pels-english -n 80 --no-pager
curl -f http://127.0.0.1:8010/api/health
sudo nginx -t
sudo tail -n 30 /var/log/pels-backup.log
```

## 已知局限

- 没有训练个人FSRS权重；曲线有默认参数。
- 词汇解释、主题整理、迁移题覆盖仍需内容审核与扩充。
- 固定答案不是任意英语表达的通用批改器。
- 原生App/微信小程序、离线同步、多用户没有实现。
- iOS键盘动画跟手不能保证和原生App一致。
- Ubuntu离线声音与Windows Zira不同；音频不在自动数据库ZIP中。
- 未实际演练灾难恢复，不能把校验成功写成恢复演练成功。
- 当前备份策略两端最多2份；服务器规则需安装后生效，详见08。
- 本机源码根目录与发布用克隆是两份；后续维护必须主动同步。
- 文档和构建中的配置与实际服务器可漂移，服务器只读核查结果优先。

## 后续AI接手必须遵守

1. 先看00索引，确认当前任务属于本地、GitHub还是服务器。
2. 检查实际文件、Git状态、远端和未提交改动，不覆盖其他项目。
3. 不读取或输出私钥、密码、token和真实.env；需要登录走正常交互授权。
4. 不重置learning.db，不把测试结果写入真实库，不把本地记录覆盖线上。
5. 算法变更用隔离库测试混合反馈、漏学、重复提交、改选、跨日与重启。
6. 低风险样式改动做构建/针对性UI检查；涉及真机限制要如实说不能验证。
7. 发布必须包含构建产物，确认/eng/路径；不顺手改原/api或根域跳转。
8. 更新前检查备份，操作完验证，明确“已推Git”和“已上线”区别。
9. 不宣称未实现功能已完成；发现历史文档与代码冲突时标注并修正。
10. 用户偏好简单直接，完成后简要报告结果、验证与未完成事项，不把长篇实现细节塞进界面。

## 本文档维护

每次改动算法、数据库、域名/端口、部署目录、账号方式、备份任务、App形式或Git工作区，都应更新相应说明和日期。新增字段应同步结构快照，不导出真实答案和学习历史进文档。
