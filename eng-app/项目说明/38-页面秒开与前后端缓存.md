# 页面秒开与前后端缓存

2026-11-07，本地完成，待推送。目标：词典、学习档案进入即显示（缓存秒开），今日学习恢复与下一题减少重复查询，计划页与当日活动合并请求。

## 前端读缓存（stale-while-revalidate）

readCache.ts 重写为 SWR 模式：命中未过期缓存立即返回；过期后先用旧数据渲染（宽限10分钟），后台静默刷新。学习类写操作（答题、反馈、介绍、跳过、设置保存）只按域失效相关页面（仪表盘/计划/当日活动/档案），其余写操作全清。设置页 TTL 5秒，词典/计划/当日活动/档案 TTL 5分钟。词典与档案进入时先显示上次数据（peekRead），不再白屏等待网络。

## 服务端响应缓存（backend/response_cache.py）

进程内缓存序列化后的 JSON 响应，按域版本号失效。单 uvicorn worker 下安全。TTL：dashboard 10秒、词典/档案/当日活动 60秒。写操作按影响范围 bump 对应域：答题类失效 dashboard+当日活动；词典导入失效词典+dashboard+当日活动+档案；设置与测试操作全失效。/api/dashboard 路由直接返回缓存字符串，跳过重复 JSON 编码；内部 dashboard() 仍返回 dict 供测试和 learning_plan 使用。

## 减少重复查询

- /api/next 内联返回题目知识元数据，省去 Study 页每题一次的 /api/knowledge/{id} 往返。
- shared_examples.prepare 增加指纹跳过：日期、数据库路径、answers 行数、progress 聚合、规则文件 mtime、admitted 数不变时直接跳过。
- composition_engine 的 Catalog 把 reviewed_facts 查询从 facts()（每次4次调用）提升到构造函数只查一次。曾试验在 prepare 加同类指纹跳过，因与惰性储库的重复调用推进语义冲突已回退，保留每次重建。
- group_learning 的 due_counts 改为两条 IN 批量查询；events()/members() 恢复事务级 memoize（selection_cache）。
- 前端 DailyLimits 与 DailyOverview 使用同一 URL（/api/daily-activity?planning=true），readCache 合并并发为一次请求。

## 验证范围

独立测试数据目录，unittest 全量：67 项测试，64 项通过。3 项失败为历史遗留（test_check_failure_then_correction_not_independent、test_error_repairs_the_actual_word_without_restarting_family、test_forgotten_and_actual_spelling_error_keep_repair），已用 git 基线（github-ether HEAD 提取的原始后端）复现确认与本次改动无关。前端 TypeScript 检查与 Vite 生产构建通过。

未验证：线上延迟实测、iOS 真机、长并发下缓存一致性（单 worker 假定）。缓存均为只读派生数据，写操作即时失效；不改变 FSRS、排课、掌握判定与原始学习记录。
